Учебный проект — сканер безопасности веб-сайтов (МЭИ, Проектная деятельность).

## Что проверяет

- Открытые порты (80, 443, 22, 3306, 8080)
- SSL-сертификат (валидность, срок действия, издатель)
- HTTP-заголовки безопасности (CSP, X-Frame-Options, HSTS, X-Content-Type-Options)
- Версию веб-сервера

## Стек

- Node.js + Express (бэкенд)
- Vanilla JavaScript + CSS (фронтенд)
- GitHub Actions (CI)

## Запуск

```bash
npm install

# Требуется PUBLIC_ORIGIN — origin, с которого открывается фронтенд
PUBLIC_ORIGIN=http://localhost:3000 npm start
```

Открыть: http://localhost:3000

> Переменная `PUBLIC_ORIGIN` **обязательна**. Если не задана — сервер откажется запускаться. Это защита от случайного открытия CORS для всех доменов.

### Переменные окружения

Переменные передаются прямо перед командой запуска. Пример:

```bash
PUBLIC_ORIGIN=http://localhost:3000 npm start
```

Шаблон переменных — в `.env.example`. При необходимости можно скопировать его в `.env`:

```bash
# Linux / macOS / Git Bash
cp .env.example .env

# Windows (PowerShell)
Copy-Item .env.example .env
```

Доступные переменные:

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт, на котором запускается сервер |
| `PUBLIC_ORIGIN` | — | **Обязательно.** Origin фронтенда для CORS (например, `http://localhost:3000`) |
| `DEMO_MODE` | `false` | Разрешает сканирование `localhost` (только при `NODE_ENV=development`) |
| `NODE_ENV` | — | `development` или `production`. Влияет на `DEMO_MODE` и обработку ошибок |

**Важно:** настоящий `.env` не попадает в Git — он добавлен в `.gitignore`.

> **Примечание:** код читает переменные из окружения процесса. Файл `.env` не подгружается автоматически — переменные задаются перед командой запуска, либо через `--env-file=.env src/server.js` (Node 20.6+).

### Режим демонстрации

Для локальной демонстрации на `localhost` (тестовый стенд) нужны **две** переменные:

```bash
PUBLIC_ORIGIN=http://localhost:3000 DEMO_MODE=true NODE_ENV=development npm start
```

Требуется явное `NODE_ENV=development`. Если `NODE_ENV` не задан или не `development` — сервер откажется запускаться с `DEMO_MODE=true`. Это защита от случайного включения демо-режима в продакшене.

**В продакшене `DEMO_MODE` не включается** — внутренние адреса остаются заблокированными.

## Безопасность и ограничения

### Что реализовано

- **SSRF-защита** — резолв DNS, проверка **всех** полученных IP на публичность, сканирование **по IP** (защита от DNS rebinding). Блокируются: loopback, private, link-local, CGNAT, multicast, ULA.
- **Строгая валидация входа** — тип и длина `url`, `consent === true`, `consentTimestamp` — число в допустимом окне.
- **Парсинг через `new URL()`** — отсекает octal/hex/decimal-формы IP.
- **Свой error handler** — наружу только JSON без стека.
- **`helmet`** — CSP, X-Frame-Options, Referrer-Policy, отключён `X-Powered-By`.
- **CORS с явным `PUBLIC_ORIGIN`** — без fallback на `*`.
- **Таймауты** на всех сетевых операциях (3–5 с на бэкенде, 30 с на фронте).
- **Лимит тела запроса** — 8 КБ.
- **Никаких эксплуатаций уязвимостей** — сканер только собирает открытую информацию.

### Известные ограничения

- **Cooldown 10 секунд ключуется по IP.** Обходится распределённым источником (IPv6-подсеть, ботнет). За прокси без `trust proxy` — все клиенты делятся одним окном. Для публичного развёртывания нужен внешний rate-limit (например, `express-rate-limit` + Redis).
- **Согласие — UX-подсказка, а не техническая защита.** `consent: true` отправляется клиентом и подделывается в одну строку (`curl`). Механизм фиксирует намерение пользователя, но не верифицирует владение доменом.
- **Свежесть согласия** защищает от повторного использования старого timestamp, но timestamp — клиентский.
- **Логирование** пишет `hostname` и IP клиента в консоль. Ротации и TTL нет.
