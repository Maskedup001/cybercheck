Учебный проект — сканер безопасности веб-сайтов (МЭИ, Проектная деятельность).

Документация: [архитектура и модель угроз](docs/architecture.md) · [политика безопасности](.github/SECURITY.md) · [DISCLAIMER](DISCLAIMER.md).

## Что проверяет

- Открытые порты (80, 443, 22, 3306, 8080)
- SSL-сертификат (валидность, срок действия, издатель)
- HTTP-заголовки безопасности (CSP, X-Frame-Options, HSTS, X-Content-Type-Options)
- Версию веб-сервера

## Стек

- Node.js + Express (бэкенд)
- Vanilla JavaScript + CSS (фронтенд)
- GitHub Actions (CI)

## Запуск

```bash
npm install

# Требуется PUBLIC_ORIGIN — origin, с которого открывается фронтенд
PUBLIC_ORIGIN=http://localhost:3000 npm start
```

Открыть: http://localhost:3000

> Переменная `PUBLIC_ORIGIN` **обязательна**. Если не задана — сервер откажется запускаться. Это защита от случайного открытия CORS для всех доменов.

### Переменные окружения

Переменные передаются прямо перед командой запуска. Пример:

```bash
PUBLIC_ORIGIN=http://localhost:3000 npm start
```

Шаблон переменных — в `.env.example`. При необходимости можно скопировать его в `.env`:

```bash
# Linux / macOS / Git Bash
cp .env.example .env

# Windows (PowerShell)
Copy-Item .env.example .env
```

Доступные переменные:

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт, на котором запускается сервер |
| `PUBLIC_ORIGIN` | — | **Обязательно.** Origin фронтенда для CORS (например, `http://localhost:3000`). Указывать без завершающего слэша, иначе он не совпадёт с заголовком `Origin` от браузера |
| `DEMO_MODE` | `false` | Разрешает сканирование `localhost` (только при `NODE_ENV=development`) |
| `NODE_ENV` | — | `development` или `production`. Включает `DEMO_MODE`. На утечку стека в ответах **не влияет**: свой error handler отдаёт JSON без деталей всегда |
| `TRUST_PROXY` | `0` | Количество доверенных прокси перед сервером (1 — для Render). Включать **только** если приложение недоступно напрямую: при `>0` адрес клиента берётся из `X-Forwarded-For` |

**Важно:** настоящий `.env` не попадает в Git — он добавлен в `.gitignore`.

> **Примечание:** код читает переменные из окружения процесса. Файл `.env` не подгружается автоматически — переменные задаются перед командой запуска, либо через `--env-file=.env src/server.js` (Node 20.6+).

### Режим демонстрации

Для локальной демонстрации на `localhost` (тестовый стенд) нужны **две** переменные:

```bash
PUBLIC_ORIGIN=http://localhost:3000 DEMO_MODE=true NODE_ENV=development npm start
```

Требуется явное `NODE_ENV=development`. Если `NODE_ENV` не задан или не `development` — сервер откажется запускаться с `DEMO_MODE=true`. Это защита от случайного включения демо-режима в продакшене.

**В продакшене `DEMO_MODE` не включается** — внутренние адреса остаются заблокированными.

## Тестирование

```bash
npm test          # node --test test/net-guard.test.js
```

Покрыто: классификация IP-адресов в SSRF-защите (`isPublicIp`) — 24 адреса в обе стороны (приватные и служебные блокируются, публичные разрешаются) плюс fail-closed на мусорный ввод. Это та часть, на которой держится вся защита от SSRF, и она проверяется без сети.

Не покрыто: `resolvePublicIps` (внутри вшит `dns.lookup`), `rateKey`, HTTP-слой (`server.js` выполняет `exit`/`listen` при импорте). Как это закрыть — в [архитектуре](docs/architecture.md), раздел «Тестирование».

## Деплой

Четыре шага, которых достаточно для публичного запуска:

```bash
NODE_ENV=production \
PUBLIC_ORIGIN=https://ваш-домен \
TRUST_PROXY=1 \
npm start
```

```powershell
# Windows PowerShell
$env:NODE_ENV="production"; $env:PUBLIC_ORIGIN="https://ваш-домен"; $env:TRUST_PROXY="1"; npm start
```

- **`NODE_ENV=production`** — боевой режим Express. На утечку стека не влияет (за это отвечает свой error handler), но убирает отладочные тексты 404 и лишний вывод.
- **`PUBLIC_ORIGIN`** — ровно тот origin, с которого открывается фронтенд. Схема и порт должны совпадать.
- **`TRUST_PROXY`** — только если перед приложением стоит прокси (nginx, Render, Cloudflare) и приложение **недоступно напрямую**. Иначе значение `1` позволит клиенту подделать свой адрес.
- **Внешний rate-limit** — обязателен. Встроенный ограничитель живёт в памяти процесса и обходится распределённым источником; см. «Известные ограничения». На PaaS (Render, Railway) переменные задаются в панели, а не в командной строке.

`DEMO_MODE` в продакшене не включается: сервер откажется запускаться, если `NODE_ENV` не `development`.

## Безопасность и ограничения

### Что реализовано

- **SSRF-защита** — резолв DNS, проверка **всех** полученных IP на публичность через аллоулист `ipaddr.js` (разрешён только `unicast`), сканирование **по IP** (защита от DNS rebinding). Блокируются: loopback, private, link-local, CGNAT, multicast, ULA, 6to4, Teredo, NAT64, IPv4-mapped и устаревший IPv4-compatible `::/96`.
- **Строгая валидация входа** — тип и длина `url`, `consent === true`, `consentTimestamp` — число в допустимом окне.
- **Парсинг через `new URL()`** — отсекает octal/hex/decimal-формы IP.
- **Свой error handler** — наружу только JSON без стека.
- **`helmet`** — CSP, X-Frame-Options, Referrer-Policy, отключён `X-Powered-By`.
- **CORS с явным `PUBLIC_ORIGIN`** — без fallback на `*`.
- **Таймауты** на всех сетевых операциях (3–5 с на бэкенде, 30 с на фронте).
- **Лимит тела запроса** — 8 КБ.
- **Никаких эксплуатаций уязвимостей** — сканер только собирает открытую информацию.

### Известные ограничения

- **Cooldown 10 секунд ключуется по IP.** IPv4-mapped приводится к IPv4, IPv6 — к подсети `/64`, нераспознанный адрес попадает в общий бакет. Обходится распределённым источником (выделенная `/48` — это 65 536 подсетей `/64` — или ботнет). За прокси без `trust proxy` — все клиенты делятся одним окном. Для публичного развёртывания нужен внешний rate-limit (например, `express-rate-limit` + Redis).
- **Согласие — UX-подсказка, а не техническая защита.** `consent: true` отправляется клиентом и подделывается в одну строку (`curl`). Механизм фиксирует намерение пользователя, но не верифицирует владение доменом.
- **Свежесть согласия** защищает от повторного использования старого timestamp, но timestamp — клиентский.
- **Логирование** пишет `hostname` и IP клиента в консоль. Ротации и TTL нет.
